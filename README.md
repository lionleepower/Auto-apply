# auto-apply · 网申表单自动填写（只填不交）

根据本地资料（`profile.yaml`）自动填写校招 / 海外网申表单。规则优先，AI 兜底；**从不点击提交 / 投递**，填完由你检查后自己提交。

- 普通用户看 [`使用手册.md`](使用手册.md)：三步上手、插件用法、常见问题
- 测试方法（含给 AI agent 直接复用的实测流程）看 [`TESTING.md`](TESTING.md)

---

## 一、功能总览

### 1. 资料与简历

| 功能 | 说明 |
|---|---|
| 一份资料、多份简历 | 基本信息（含证件信息）所有简历共用；教育 / 经历 / 项目 / 论文 / 技能 / 自我评价 / 简历文件每份一套。类型分「中文（国内校招）」和「海外（英文表单）」，可设默认、复制、改名 |
| 知识库整理 | 上传简历 PDF / Word，或把自我介绍、零散信息贴进「知识库」，点「AI 整理进资料」。默认只补空，不覆盖手改过的内容；重复整理不产生重复经历；18 位证件号发给 AI 前先打码 |
| 缺失项检查 | 按简历类型列出缺什么（红＝几乎每张表都要，黄＝建议补充），点一下跳到对应输入框 |
| 常用问答 | 「是否有亲属在本公司任职 → 否」这类每家都问的问题：关键词（`|` 分隔）→ 答案，优先于其他规则；答案可写多个说法（`否、没有、无`） |
| 备选值 | `新加坡 / 苏州`（带空格的斜杠或「或」）：网站选不到前一个就用后一个；`江苏/苏州`（不带空格）是路径 |
| 「至今」 | 结束时间写「至今 / 现在 / present」时，日期框里填当前年月 |
| 证件号开关 | 默认永不自动填写（页面上标紫提醒手填）；资料里勾选「允许助手自动填写证件号」后才会填 |
| 旧格式兼容 | 旧版平铺的 `profile.yaml` 读取时自动当作一份「默认简历」，第一次保存时转成新格式；保存前备份为 `profile.yaml.bak` |

### 2. 填写引擎（页面脚本 `src/autofill/js/autofill.js`，插件和命令行共用同一份）

| 功能 | 说明 |
|---|---|
| 字段识别 | 标签来源：`label[for]`（从近到远）、`aria-labelledby`、共用标签、控件前紧挨的小标签（「GPA/CGPA」）、占位文字；分区按标题链识别（含 Tailwind 字重标题），列表分区（教育 / 实习 / 项目…）按段编号 |
| 规则映射 | 标签正则 + 分区 → 资料键（`rules.py`）；同标签连续控件配对（起止时间、国家 / 省 / 市）；同一资料项的第 n 个框取第 n 个值（「其他意向城市 1/2」）；「有 / 没有」闸门按资料里有没有这类经历选 |
| AI 兜底 | 规则认不出的**有标签**字段交给 AI，只发「标签 + 选项 + 资料键目录」，**不发资料值**；坏 JSON / 编造的键一律当未识别 |
| 补齐段落 | 资料里有 3 段教育、页面只有 1 段时，自动点「添加」补齐 |
| 分区编辑式表单 | OPPO 这类「点铅笔才可编辑、每个分区单独保存」：逐个打开资料里有内容的分区 → 填 → 可选点「保存」→ 下一个；填完冒出的新字段（选了「有」才展开的表单）下一轮接着填 |
| 真实点击 | Element Plus 等不认脚本点击：页面把点击 / 键盘请求排队，由驱动做真实输入（命令行用 Playwright 鼠标键盘，插件用 Edge 调试接口）。点之前先等元素站稳（弹层展开动画结束）再量坐标、做命中检测，被挡住才退回脚本点击 |
| 填后核对 | 每次点选都核对控件上是否真的显示了选中值；没生效就标黄「请确认」，绝不偷偷改 `checked` |
| 页面已有值 | 一致就保留（日期按页面精度比，脱敏手机号按通配比）；不一致默认只标黄，勾「覆盖」或刚上传过简历（站点解析写错）时改成资料值 |
| 提示框处理 | 点「保存」后弹的「保存前请确认以上经历」这类保存确认框点「确认」；其他提示框一律「取消」；提到提交 / 投递 / 删除 / 离开的框永不点确认 |
| 被锁定的框 | 网站自动带出且禁用的下拉（OPPO 选学校后的「国家」）：等它解锁或核对带出的值，不报失败 |
| 资料覆盖率 | 报告列出「这张表没地方填的资料」（如没有项目栏），提醒你在其他栏里提一句 |

### 3. 浏览器插件（`extension/`，Edge 侧边栏）

- 在你自己已登录的网申页上直接填：「填写本页」「只预览」「停止」「导出诊断」
- 显示公司、截止日期和内推码（从链接参数或投递表里找），可手改
- 选项：先上传简历、覆盖不一致的值、AI 兜底、填完点分区「保存」；「使用简历」下拉（多份简历时）
- **多页面并行**：每个标签页各自一份任务状态；在 A 页点「填写本页」后可以直接切到 B 页再点，切回哪页就显示哪页的进度和结果，底部提示还有几页在填
- 结果：分区保存结果（失败时原样列出网页报错和处理过的弹框）、「需要你处理」（点一下跳到字段）、「这张表没地方填的资料」
- 页面高亮：🟩 已填　🟨 待确认　🟥 未填　🟪 敏感字段

### 4. 桌面助手（`打开自动填写助手.bat`）

独立窗口（Edge 应用模式，关窗口即停止服务）：「我的资料」（多简历、知识库、缺失项、分区折叠的资料表单）、「AI 接口」、「上手向导」（含安装插件的按钮）。插件依赖它提供的本地服务（127.0.0.1:8765）。

### 5. AI 接口

DeepSeek、通义千问、Kimi、智谱、豆包、OpenAI、OpenRouter、Ollama（本地）、Claude、Gemini 原生协议，以及任意 OpenAI 兼容地址。可配多家，按顺序优先，**报错 / 限流 / 欠费时自动换下一家**。Key 存在 `settings.json`（`.env` 里的 `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` 仍然有效）。

### 6. 命令行与批量投递

| 命令 | 作用 |
|---|---|
| `autofill gui` | 打开桌面助手 |
| `autofill serve [--port]` | 只启动插件用的本地服务 |
| `autofill login` | 在独立浏览器配置（`.browser-data-msedge`）里登录各网申站（一次即可） |
| `autofill fill <url> [--dry-run] [--overwrite] [--upload-resume] [--referral 码]` | 用独立浏览器打开网申页并填写；多页表单翻页后回车继续 |
| `autofill batch [--list] [--only 公司,…] [--ats moka] [--industry …] [--redo]` | 按投递表（xlsx）逐家打开、自动带内推码；进度记在 `runs/applications.csv`，已填的跳过 |
| `autofill audit [diag 文件] [-v]` | 离线审计：用导出的诊断重跑字段识别，看还有哪些认不出 |
| `autofill demo <名字>` | 在本地 demo 表单上演示 |

全局选项：`--profile`、`--llm deepseek|qwen|…`、`--browser msedge|chrome`（默认 Edge，各自独立登录状态）。

### 7. 诊断与适配

- 插件「导出诊断」：逐个打开下拉 / 日期控件，记录真实结构到 `runs/diag-*.json`（不含资料值，不填任何东西）
- `autofill audit` 离线重跑识别；脱敏后的诊断放进 `tests/fixtures/` 成为回归测试
- 每次填写都写报告 `runs/run-*.json`：每个字段的识别、候选值、结果、原因，分区保存结果，未用上的资料

## 二、安全与隐私原则

| 原则 | 实现 |
|---|---|
| 只填不交 | 永不点提交 / 投递 / 保存并提交；「保存」只认文字恰好是「保存」的按钮，且要勾选项才点 |
| 资料不出本机 | 本地服务只监听 127.0.0.1，只接受插件来源（`chrome-extension://`）和本机地址的请求，普通网页读不到资料 |
| AI 只看字段，不看资料 | 填表时只发标签 / 选项 / 资料键目录；只有「AI 整理」时知识库文字才会发出，证件号先打码 |
| 证件号 | 默认永不自动填写，需在资料里显式打开 |
| 登录与验证码 | 永远由你自己完成 |
| 不编造 | 资料里没有的事实（GPA、排名、日期、导师…）一律留空标红，不猜 |
| 密钥与个人文件 | `profile.yaml`、`settings.json`、`.env`、`resume/`、`runs/`、`.browser-data*/`、`tools/live/sites.json` 都在 `.gitignore` |

## 三、快速上手

1. 双击 **`打开自动填写助手.bat`**，在「我的资料」里录入资料（上传简历 / 贴进知识库 → AI 整理 → 补缺失项 → 保存）
2. 「上手向导」第 3 步：在 `edge://extensions` 打开开发人员模式 →「加载解压缩的扩展」选 `extension/` 文件夹 → 固定到工具栏
3. 在 Edge 里登录、打开职位申请表 → 点插件图标 →「填写本页」→ 看「需要你处理」→ **自己提交**

> 改了 `src/autofill/js/autofill.js` 后，重启服务会自动同步到 `extension/autofill.js`；再到 `edge://extensions` 点插件的「重新加载」。

命令行示例：

```bash
.venv\Scripts\autofill fill "https://job.xiaohongshu.com/campus/position/21007/apply" --dry-run
.venv\Scripts\autofill --llm deepseek batch --list
.venv\Scripts\autofill --llm deepseek batch --ats moka
```

## 四、工作原理

```
                 ┌─────────────── 页面里（autofill.js，插件 / 命令行共用） ───────────────┐
网申页 ──抽取──▶ │ 字段（标签 / 分区 / 选项 / 当前值）· 添加按钮 · 分区编辑按钮 · 保存按钮 │
                 └──────────────────────────────┬──────────────────────────────────────┘
                                                ▼
          本地（pipeline.py / server.py）：规则映射 → AI 兜底 → 取资料值、换格式 → 决定填不填
                                                ▼
          页面里逐个填写：要点击 / 打字时排队 ──▶ 驱动做真实输入（Playwright / Edge 调试接口）
                                                ▼
                     核对 → 高亮 → 报告（runs/run-*.json）→ 你检查后自己提交
```

| 文件 | 作用 |
|---|---|
| `src/autofill/js/autofill.js` | 页面内逻辑：字段抽取、各类控件的填写与核对、分区展开 / 保存、提示框处理、高亮、诊断 |
| `src/autofill/rules.py` | 分区识别、标签 → 资料键规则（中英文）、日期格式、选项同义词、地区拆分与备选值 |
| `src/autofill/pipeline.py` | 规划（`plan` / `resolve` / `prepare`）、结果合并、报告；命令行驱动 `run()`（多轮、分区保存） |
| `src/autofill/profile.py` | 资料模型：基本信息 + 多份简历、常用问答、证件号开关、旧格式迁移 |
| `src/autofill/llm.py` / `settings.py` | AI 兜底映射；多厂商配置与故障转移 |
| `src/autofill/server.py` | 插件后端（FastAPI，127.0.0.1:8765）：`/plan`、`/finish`、`/expand`、`/next-section`、`/resume`、`/diag`… 会话按时间清理，支持多页并行 |
| `src/autofill/gui.py` / `knowledge.py` / `ui/` | 桌面助手：知识库抽取、缺失项检查、界面 |
| `src/autofill/batch.py` / `coverage.py` / `audit.py` | 投递表读取与进度；资料覆盖率；离线审计 |
| `extension/` | Edge 插件：`flow.js`（一次「填写本页」的完整流程，测试也直接跑它）、`sidepanel.*`（界面，按标签页分开的状态） |
| `demo/*.html` | 带标准答案的测试表单：飞书 / AntD、北森、Moka、飞书 ud、小红书复刻、北森 + OPPO 风格复刻 |
| `tests/` | 离线测试（见 TESTING.md） |
| `tools/live/` | 真实站点实测脚本（见 TESTING.md） |

## 五、支持的控件

| 控件 | 做法 |
|---|---|
| 文本框 / 多行文本（含 React 受控组件） | 原生 setter + input/change 事件；远程搜索框用真实键盘输入 |
| 原生 select、单选组（含 div 画的单选） | 按选项文字匹配（同义词：硕士 ↔ 硕士研究生）；完全相同 > 以候选开头 > 包含 |
| 自定义下拉（AntD / Element Plus / 北森 / 飞书 ud） | 依次尝试外层包装 → 输入框 → 图标打开；只认新弹出的选项；选后核对 |
| 多选（意向城市、开发语言） | 逐个点选，弹层底部有「确定」就点 |
| 可搜索 / 远程搜索下拉（学校） | 匹配不到 → 输入关键词 → 等结果再选 |
| 地区选择器（北森：省 → 市 → 区） | 逐级点选；最后一级点选择图标 +「确定」；网站只到市一级时不算失败；多个备选路径依次试 |
| 国家 / 省 / 市分开的三个下拉（OPPO） | 从最具体的一级往上匹配；锁定的一级等网站带出 |
| 日期选择器（含只读、月份面板、Element 图标按钮、北森 phoenix） | 先尝试输入 + 回车；不行就打开面板按年 / 月翻页点选；日级面板只有年月时选 1 日 |
| 范围日期（起止时间） | 两个日期依次填，各自核对 |
| 级联选择（国家 / 学校、省 / 市） | 值拆成路径逐级匹配，直辖市自动补第二级 |

| 小红书校招 | 2026-10-07 | 分区标题是 Tailwind 的 `text-h6 font-medium`，class 里没有 title | 按字重识别标题，并取标题链中第一个能识别的 |
| | | 两个日期框共用「起止时间」label，而且 id 都是 `_startDate` | 依次用占位文字（入学 / 毕业时间）、前后顺序、id 判断 |
| | | 「论文」和「竞赛」的 id 都是 `resumePaperInfo_0_name` | 从控件往外找最近的 `label[for]` |
| | | 无标签的证件类型 / 区号下拉被模型猜成证件号和籍贯 | 无标签字段不交给模型 |
| | | 单选没有 name；意向城市是多选；发布渠道是 AutoComplete | 按 radio-group 分组；多选全选；AutoComplete 保留输入文字 |
| | | 上传简历后站点解析写错：专业「数据」、日期张冠李戴、勾上「至今」 | 本次上传过简历时以资料为准改回；有结束时间时取消「至今」 |
| | | 账号预填的手机号是脱敏的 `188****6898` | 按通配比较，视为一致 |
| OPPO 校招（Element Plus） | 2026-10-08 | 脚本模拟的点击一律不响应 | 改用真实点击：命令行用 Playwright 鼠标，插件用 Edge 调试接口（填写期间顶部有「正在调试」提示条） |
| | | 分区默认只读，点铅笔才出现输入框；每个分区单独「保存」 | 逐个打开资料里有内容的分区 → 填 → 可选点「保存」并核对；保存失败把网页报错原样带回 |
| | | 「工作经历：没有 / 有」选「有」才展开表单 | 按资料里有没有这类经历选；新冒出的字段下一轮接着填 |
| | | 学校名称是远程搜索、标签是 div + aria-labelledby、国家/省/市三个下拉共用一个标签、外层叫 cascade-select | 真实键盘输入搜索词；读 aria-labelledby；从最具体的一级往上匹配；装着多个下拉的容器不算下拉 |
| | | 选项打分只看「包含」，「利物浦大学」选成「西交利物浦大学」 | 完全相同 > 以候选开头 > 包含（多出的字越少越好） |
| | | 保存失败后 Element Plus 给 `<body>` 加 `el-popup-parent--hidden`，「弹层里的不算字段」把整页下拉都排除了 | 判断弹层时不算 body / html |
| | | 点「保存」弹「保存前请确认以上经历」，没人处理，遮罩越叠越多，后面的点击全落在遮罩上 | 刚点完「保存」弹的保存确认框点「确认」，其他提示框点「取消」；报告记下每个处理过的弹框 |
| | | 「年级成绩排名」里下拉后面的输入框其实是「GPA/CGPA」，被填成了排名 | 识别控件前紧挨的小标签 |
| | | 选了学校后「国家」自动带出并禁用 | 等它解锁或核对带出的值，不报「打不开」 |
| | | 已保存的分区重新打开时，学历先显示选项编码「20 / 30」 | 打开分区后等编码变成文字（最多 8 秒）再读 |
| | | 基础信息缺照片 / 证件时，其他分区也被判「没保存成功」 | 按这个分区自己的「保存」按钮是否消失判断 |

| | | 月份日历的外层 class 带 header，把格子也包进去了 | 只把不含格子、带年份的那块当标题 |

## 八、已知局限

- 附件上传（简历除外）、协议勾选、个人照片一律不碰
- 开放式问题（「为什么选择我们」）还不生成草稿
- 富文本编辑器（contenteditable）、拖拽排序还不支持
- 英文月份名下拉（“Jan 2023”）的日期控件还不支持
- 日期面板识别依赖常见 class 名（header / cell / prev / next 等）；完全自绘的日历要按站点补适配
- 同一家公司的简历不要同时在两个标签页里填（两边会互相覆盖草稿）
